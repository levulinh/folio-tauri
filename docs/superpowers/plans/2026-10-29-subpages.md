# Inline subpages (owner request, 2026-10-29)

Goal: create a child page from inside the page you are writing, Notion-style, without leaving the editor to the sidebar.

## Scope

- A new leaf block `folioSubpage` holding one prop, `pageId`. It renders as a row with a page icon and the child's **live** title; clicking it opens that page through the existing `openPage` (flush + toast/`not_found` handling).
- Slash-menu item **Subpage** (`/subpage`, `/page`, `/trang con`) creates the page under the open page, inserts the row at the caret, expands the parent in the sidebar, then opens the child with its title focused.
- The row is a link, not an owner: deleting the block leaves the page; deleting the page leaves a disabled "Trang đã bị xoá" row in the parent. Neither direction deletes data implicitly.
- Works at any depth: the parent is whatever page is open, so a child can itself contain subpages.

Out of scope: inline title editing inside the row, picking an existing page (that is the spec's later "Page link" chip), moving pages, and Markdown export of the row (export is a later phase).

## Interfaces

```ts
// ui/src/editor/subpage/index.tsx
export const subpageSpec;                          // type "folioSubpage", propSchema { pageId: string }
export async function insertSubpage(editor: FolioEditor): Promise<string | null>;
```

`insertSubpage` reads the open page from `usePageStore`, creates the child with `usePagesStore.create`, inserts through `insertOrUpdateBlockForSlashMenu` (so an empty block or a lone `/query` is replaced), then sets `useExpandedStore`, `requestTitleFocus` and `openPage`. If the user switched pages during the await, the page is still created but no row is inserted into a stale editor.

Stored shape is the ordinary block node: `{ type: "folioSubpage", props: { pageId }, content: null, children: [] }`. The backend already stores arbitrary block props; search text for the block is empty, and the child's own title is indexed as a page.
